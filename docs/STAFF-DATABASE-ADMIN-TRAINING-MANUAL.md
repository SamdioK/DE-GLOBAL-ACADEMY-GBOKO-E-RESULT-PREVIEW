# Staff Database — Administrator Operational and Training Manual

**Project:** DE-GLOBAL ACADEMY GBOKO E-Result Portal  
**Module:** Staff Database  
**Audience:** School Administrator and authorised staff-record administrators  
**Repository:** `SamdioK/DE-GLOBAL-ACADEMY-GBOKO-E-RESULT-PREVIEW`  
**Status:** Operational guide for the current Supabase-connected preview implementation  
**Last updated:** 6 November 2026

## 1. Purpose

The Staff Database is the school's controlled directory of staff records. It allows an authorised administrator to create a staff record, review existing records, correct information and decide individually whether a record may appear on the public school portal.

The module uses the existing Supabase `school_staff_directory` table. It does not treat browser storage as the authoritative staff record store.

**Important:** The preview and live portals use the same Supabase project. A successful save from either portal changes the shared school database. Use care when editing real staff records.

## 2. Roles and permissions

### School Administrator
The administrator is responsible for:
- viewing the school's staff directory;
- creating staff records where a record does not already exist;
- editing verified staff information;
- changing a staff record's status;
- deciding whether an individual record is visible on the public portal; and
- checking the completeness summary.

The current database controls restrict staff-directory reads and writes to an authenticated administrator belonging to the same school. The browser must use the public Supabase client key only. Row Level Security (RLS) remains enabled.

### Other users
The Staff Database administration screen is not an alternative route for Form Masters, students or unauthorised users to edit staff records. Do not share an administrator account or bypass the application's role checks.

## 3. Opening the module

1. Open the school's E-Result Portal.
2. Sign in using the authorised school administrator account.
3. Open the administrator dashboard.
4. Select **Staff Database**.
5. Allow the directory to load from Supabase.
6. Confirm that the expected existing staff records appear before making changes.

If the records do not load, do not recreate them. Record the error message and ask the system administrator to investigate the sign-in, school profile, network connection and Supabase access.

## 4. Understanding the screen

The screen contains the staff record form, a **Staff Record Completeness** summary, a search field and the staff records list.

### Staff record fields

| Field | How the administrator should use it |
|---|---|
| Staff ID | Enter the school's approved ID manually, if one has been assigned. It is not generated by the system and may remain blank. |
| Full Name | Enter the staff member's verified name. This is required. |
| Gender | Select the verified option: Male, Female or Others. |
| Designation / Position | Enter or select the staff member's actual position. |
| Department | Select the appropriate department. If **12. Others** is selected, complete the accompanying department description. |
| Qualification | Select the qualifications supported by the staff member's records. A maximum of eight selections is allowed. NCE is labelled **Nigeria Certificate in Education**. |
| Specialisation | Enter the verified subject, professional or area-of-specialisation information. |
| Employment Type | Select Full Time, Part Time, Visiting Staff or Contract Staff, as applicable. |
| Phone and Email | Enter current, verified contact details where authorised. |
| Date Employed | Enter the confirmed employment date. Do not estimate it. |
| Biography | Add a factual professional summary if required. |
| Photo | New photo uploads are currently unavailable pending verification of Supabase Storage permissions. |
| Account Status | Use Active, Inactive or Suspended in accordance with the school's administrative decision. |
| Show on School Portal | Enable only after the record has been checked and approved for public display. |

## 5. Completing an existing staff record

Use this workflow for the existing staff members whose profiles are incomplete.

1. Find the staff member using the search field. Search by name or another displayed identifying field.
2. Open the relevant record using its edit action.
3. Confirm the person's identity before changing any information.
4. Enter only information supported by the school's staff file or another authorised record.
5. Leave unknown fields blank. Do not guess a qualification, employment type, date employed, gender, department or specialisation.
6. Leave Staff ID blank if the administrator has not assigned one.
7. Keep **Show on School Portal** unchecked while the record is being completed or reviewed.
8. Save the record.
9. Wait for the success confirmation. The application saves through the authenticated Supabase update method and refreshes the displayed record from the returned saved row.
10. Reopen or review the record to confirm that the information is correct.

Repeat separately for each staff member. There is no need to create a second record for a person who is already listed.

## 6. Adding a genuinely new staff record

Only add a record when the person does not already have a staff-directory entry.

1. Search the directory carefully to avoid creating a duplicate.
2. Complete the required Full Name field and all information currently verified.
3. Enter a Staff ID only if the school has formally assigned one.
4. Keep public visibility off until the record has been reviewed.
5. Select **Add Staff Record**.
6. Confirm the success message and verify that the new row appears in the directory.

The database enforces school-scoped uniqueness for non-empty Staff IDs and email addresses, and prevents a profile from being linked to multiple staff rows in the same school. If a duplicate warning appears, stop and investigate the existing record; do not work around the constraint by changing a person's identity details.

## 7. Saving incomplete records

The school may complete staff records progressively. An administrator can save an incomplete record while it remains unpublished.

This is intentional:
- missing details remain visible in the completeness summary;
- no values are filled automatically;
- a blank Staff ID is acceptable; and
- incomplete records must not be published merely to make the summary appear complete.

## 8. Staff Record Completeness summary

The summary counts how many loaded staff records have values for:
- Staff ID;
- Gender;
- Designation;
- Department;
- Qualification;
- Specialisation;
- Employment Type; and
- Date Employed.

The summary is an audit aid, not a data-entry or correction tool. It does not change Supabase records.

**Interpretation note:** Staff ID is manually administered and optional until assigned by the school. A missing Staff ID count is not, by itself, evidence of a system fault. The publication gate does not require a Staff ID.

## 9. Public portal publication

Public visibility is an individual administrative decision, not an automatic consequence of saving a record.

Before enabling **Show on School Portal**, verify that the record is accurate and that the school has approved the information for public display. The current form requires:
- Gender;
- Designation / Position;
- Department;
- Employment Type; and
- at least one Qualification, or a preserved legacy qualification.

If a required item is missing, the form reports the missing fields and prevents publication. Complete the information from verified records first.

After the save succeeds, check the public portal separately to confirm the intended display. Do not assume that saving a staff record automatically publishes it. Keep the visibility control off for any staff member who has not been approved for public display.

## 10. Changing staff status

Use the status control only on the administrator's instruction and in accordance with school records.

- **Active:** the staff member is currently recorded as active.
- **Inactive:** the staff member is no longer active in the relevant role or employment record.
- **Suspended:** the staff record is suspended under an authorised administrative decision.

Confirm the correct person before changing status. The status action writes to Supabase. It is not a deletion. The current directory has no staff-delete workflow, and administrators must not attempt to remove records by bypassing the application.

## 11. Validation and expected outcomes

A successful save should:
1. show a success notification;
2. return the saved row from Supabase;
3. update the matching row in the displayed directory; and
4. preserve the record's existing profile link and school scope.

The following controls are expected:
- Full Name is required.
- A maximum of eight qualifications may be selected.
- Selecting **12. Others** requires a department description.
- Non-empty duplicate Staff IDs or emails are rejected by database uniqueness controls.
- Staff IDs are never generated automatically.
- Public visibility is blocked until the publication requirements are satisfied.
- New photo uploads are blocked until Storage permissions are verified.
- The application does not provide a staff deletion action.

## 12. Troubleshooting

| Problem | Recommended action |
|---|---|
| Staff list does not load | Check internet access and administrator sign-in. Capture the displayed error for the system administrator. Do not recreate the records. |
| Save fails | Read the full error. Check required fields, school access and duplicate Staff ID/email values. Retry only after correcting the cause. |
| Duplicate ID or email warning | Search for the existing record and verify the correct value. Do not invent a different ID or email to bypass the restriction. |
| Department set to Others is rejected | Enter the department description in the accompanying field. |
| More than eight qualifications selected | Reduce the selection to the qualifications supported by the staff member's records. |
| Public visibility is rejected | Complete the missing publication fields using verified information, or leave the record unpublished. |
| Photo upload is blocked | Save the record without selecting a new photo. Photo uploads are deliberately deferred until Storage permissions are verified. |
| Completeness count does not change | Confirm that the save succeeded and that the directory refreshed. Reopen the record and report persistent discrepancies. |
| Access denied | Confirm that the signed-in account has the school's administrator role. Do not weaken RLS or use a service-role key in the browser. |

## 13. Data protection and administrative rules

- Use the administrator account only for authorised school administration.
- Do not share passwords or publish private staff contact details without approval.
- Enter information from verified school records.
- Do not create duplicate staff records to correct an existing row.
- Do not delete staff records or bypass RLS.
- Do not expose Supabase secret or service-role keys in HTML, JavaScript, GitHub or browser developer tools.
- Treat the preview as connected to the shared school database, not as a disposable test database.
- Keep public visibility off until the individual record has been reviewed and approved.
- Report unexpected changes immediately.

## 14. Practical training exercise

Use an existing record selected by the school administrator. Do not create a fictitious staff member or change a real person's information for practice.

1. Locate the selected record.
2. Identify which fields are complete and which are missing.
3. Explain why a Staff ID may remain blank.
4. Enter one verified missing field and save.
5. Reopen the record and confirm the saved value.
6. Explain why the record should remain unpublished until the publication checks are satisfied.
7. Demonstrate how to find the record again using search.

The trainer should observe that the trainee does not invent information, create duplicates, change account links or enable public visibility without approval.

## 15. Completion checklist

- [ ] Administrator can open the Staff Database.
- [ ] Existing staff records load from Supabase.
- [ ] Administrator can search for and edit an existing record.
- [ ] Verified changes save and are visible after reload.
- [ ] Incomplete records can remain unpublished.
- [ ] Staff IDs remain manually assigned.
- [ ] Qualification limit and department validation work.
- [ ] Publication requirements are enforced.
- [ ] Public visibility is enabled only after individual approval.
- [ ] Photo-upload limitation is understood.
- [ ] No staff record is deleted or duplicated during training.

## 16. Known limitations and future work

The current implementation does not enable new staff photo uploads because the Supabase Storage bucket and policies have not yet been verified. Per-field public profile visibility is also deferred; the current implementation supports the record-level `show_on_portal` flag. These limitations must not be bypassed by embedding base64 photos or private data in public HTML.

Any future change to Storage, public profile fields, permissions or database schema requires a separate review, implementation and training-manual update.

---

**Training principle:** The administrator is responsible for the accuracy and publication approval of each staff record. The system provides validation and controlled storage; it does not decide or invent staff information.
